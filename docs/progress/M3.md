- KEYS: Fabric runs the mod's `init()` before the options exist, and every loader reloads `options.txt` after registration, so no re-read is needed. (R-EXP-26, D-066)

## Deviations from the docs (with reason)
- World entry is the harness's job (local dedicated server), not the testkit's template save (testing-strategy §4 updated). (D-067)
- hud-box draws no text: `Canvas2D` has no text until M4 (testing-strategy §4 updated).
- `KEY_HANDOVER` is an internal event file with `usedBy`, not an API event. (D-065, D-066)
- Forge 1.8.9 appends to `GameSettings.keyBindings` itself instead of calling `ClientRegistry.registerKeyBinding`, because a `loader:` reference cannot name 1.8.9 classes in its descriptor (events-and-hooks §4.7). (D-066)
- The `options.txt` re-read of events-and-hooks §4.7 is not built: no loader needs it. (D-066, R-EXP-26)
- NeoForge native listeners register with `register(Object)` and `@SubscribeEvent` (as in M1), not `addListener` with an explicit class (events-and-hooks §5): this form ran on NeoForge 1.21.1 in the M0, M1, M2 and M3 gates.
- `screen.open` on Fabric 26.x is bound to 26.1.2 only: `setScreen` moves to `Gui` in 26.2, which is not a core target yet (M7).
- CI job definitions (`.github/workflows/ci.yml`) are written and not run: no remote CI exists yet.
- New decisions in M3 (D-064..D-067) are marked Provisional (worker); the orchestrator wrote them from the slices' proposed text.
