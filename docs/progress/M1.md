## Where I stopped (T9, session 2)
The three open gaps from session 1 are now concrete. D-053 and D-054 cover the cast step and the glue payload source. They do not cover the three cases below, which M0 Gen.java needs for the HUD and world hooks. Each one is a binding grammar question the owner must decide. I have not picked an option.

A. **A chain step cannot take a constant argument.** M0 `HudMixin` and `WorldMixin` on fabric 1.21.1 and 26.1.2 (and neoforge 1.21.1 HUD) call `DeltaTracker.getGameTimeDeltaPartialTick(true)`. The boolean has no way onto the stack in a chain: a later step is a zero-argument invoke (section 4.3). The parser now rejects it: `chain step 1 must take no arguments (its descriptor has parameters)`. A glue member `partialTick(Object)` cannot be written.
B. **No array in the grammar.** M0 `WorldMixin` (fabric 1.21.1, 26.1.2, neoforge 1.21.1, forge 1.20.1) converts `Matrix4f` to `float[16]` with `new float[16]` and `Matrix4f.get(float[])`. No lowering kind allocates an array, and no payload source produces one. The world hook cannot be bound.
C. **No effect-only glue.** Fabric 1.21.1, neoforge 1.21.1 and forge 1.20.1 call `GuiGraphics.flush()` (void) before immediate HUD drawing. A payload value must exist and `Dispatch.hud(float)` has no slot for it, so a void glue cannot be a payload source. `glue/GlueGui.json` therefore cannot be written.

Options for the owner (none chosen):
- For A: allow an `args` list on a later chain step, whose entries are payload sources (for example `{"const": true}`); or allow `{"const": v}` as a chain step.
- For B: add an array lowering or source (for example `{"new": "[F", "length": 16}`); or move matrix conversion to adapters (M2) and bind world hooks in M2.
- For C: allow an effect-only payload entry (for example `{"glue": "...", "effect": true}`) that runs without filling a `Dispatch` parameter; or allow a hook-level action before the `Dispatch` call.
- If none is wanted in M1: the HUD and world hooks wait for M2 (adapters), and M1 binds the tick and glue subset that is done.

Resolution of the owner's decision is needed before `events/HudRender.json`, `events/WorldRender.json` and `glue/GlueGui.json` can be written. Then T10 to T12 and the gate can proceed.

## Surprises (each also in research-log or decisions)
1. LWJGL 2.9.4 is not on Maven Central (D-052, Provisional).
2. `Glue` (an abstract class with defaults) became static glue stubs with no defaults (D-052). Unused members need explicit defaults in each target's rule list: `const 0` or `-1` as in the M0 base class, `unsupported` for doubles (a `const` is an int, boolean or string, so it cannot make `0.0`). This is why GlueWorld on modern eras is `unsupported`.
3. One Mojang-named rule per era serves every loader for glue and tick. Mojang refs route to the runtime namespace (intermediary, srgmoj, mojang), so glue needs no per-loader rules. Hooks are written in runtime names, so they need per-loader rules.
4. Intermediary ids are exact to one version (section 2.4 routes them through the target's own file), so the 1.21.1 hook rules use `"mc": "1.21.1"` and do not claim the range.
5. The strict loader rejects a top-level `note` in `hooks.json` (the schema has none). Fixed before the commit.
6. Event `filter` has no spec in section 7. Used as `{key: CONSTANT}` equality, as the test fixture `HudRender.json` and events-and-hooks section 4 (`phase == END`) imply.
