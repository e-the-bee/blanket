## Surprises (each also in research-log or decisions)
1. LWJGL 2.9.4 is not on Maven Central (D-052, Provisional).
2. `Glue` (an abstract class with defaults) became static glue stubs with no defaults (D-052). Unused members need explicit defaults in each target's rule list: `const 0` or `-1` as in the M0 base class, `unsupported` for doubles (a `const` is an int, boolean or string, so it cannot make `0.0`). This is why GlueWorld on modern eras is `unsupported`.
3. One Mojang-named rule per era serves every loader for glue and tick. Mojang refs route to the runtime namespace (intermediary, srgmoj, mojang), so glue needs no per-loader rules. Hooks are written in runtime names, so they need per-loader rules.
4. Intermediary ids are exact to one version (section 2.4 routes them through the target's own file), so the 1.21.1 hook rules use `"mc": "1.21.1"` and do not claim the range.
5. The strict loader rejects a top-level `note` in `hooks.json` (the schema has none). Fixed before the commit.
6. Event `filter` has no spec in section 7. Used as `{key: CONSTANT}` equality, as the test fixture `HudRender.json` and events-and-hooks section 4 (`phase == END`) imply.

## Deviations from the docs (with reason)
- `log4j-api` is not a dependency (D-052).
- `features.json` is not loaded: not in the T4 list, needed by the `Blanket.supports` binding.
- Packet blocks (binding-format section 4.6) are not modelled: no M0-subset type has a packet view.
- Regex selectors use `Matcher.find()`, not `matches()` (spec example anchored with `^`/`$`).
- The `supported` list in `targets.json` is kept as strings; the generator `updateTargets` is not built.
- D-054 says glue members return `Object`. D-056 amends it: a glue member returns the type of the `Dispatch` parameter it fills (for example `float`, `float[]`, `double`), because D-055 keeps `Dispatch` typed. Glue parameters may be `Object`; the generator inserts a checkcast. Owner to confirm.
- binding-format.md section 7 still has the D-051 sentence "passes each payload value to `Dispatch.<event>(Object...)`". D-055 supersedes it for M1. A paragraph added to section 7 says so.
- The later-step rule of section 4.3 is enforced at parse time (a later step that takes parameters, or is a constant, put, adapter or nested chain, is an error). The spec said it; the parser did not check it before.
- Native event refs use the `loader:` namespace. Loader jars are now indexed from `loader-artifacts.json` (D-058), so the validator resolves them; they also rest on the M0 game runs.
- The git repositories: the root had no commits; the first commit (d49ea98) imports the design docs and prompts as the starting state, then T1 (8329272). This is a baseline, not a task commit.
