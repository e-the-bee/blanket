## Deviations from the docs (with reason)
- Adapters ship in `com.blanket.adapters.<set>` (lowering §5.2 vs §4.5). (D-061)
- `features.json` is read directly, with no generated `types/Blanket.json` (binding-format §6, example 10). (D-061)
- Key code tables are Java in each set's `KeyCodes` adapter, with no `types/Key.json` (api-surface §3.9). (D-061)
- `KeyBinding.register` is bound, but its per-loader registration recipe is M3 (events-and-hooks §4.7, S-07). (D-061)
- Stub bodies throw `AssertionError("blanket stub")` per api-surface §1 rule 5 (M1 code threw UnsupportedOperationException). (D-061)
- `Screen` ships without `add`/`remove` until widgets (M6). (D-061)
- C10 baseline is the T1 jar, since no release exists (D-060). (D-061)
- Remapped adapters stay in `blanket-bindings/build/adapters/` in M2, because a bindings-jar package would make a Gradle task cycle. (D-061)
- M1-verify finding 5 (`lookup` cannot resolve `loader:` references) is deferred to M3, where native events grow. (D-061)
